## Executive summary

The Claude Code plugin ecosystem matured rapidly between Q4-2025 and Q2-2026, driven by the introduction of marketplace manifests and the `disable-model-invocation` flag for commands [1][2]. The current community consensus is that **thin Bash forwarders** outperform Node.js companion runtimes for single-purpose plugins, that **subagents in `agents/`** are the right primitive for reusable LLM-to-LLM delegation, and that **slash commands should default to foreground execution** with explicit `--background` opt-in [3][5]. Plugins published as marketplaces (rather than bare plugin folders) are easier to discover and version-pin [4]. The most-starred plugins in 2026 share three traits: a one-line install, a single killer slash command, and a written-to-file output path that survives the conversation.

## Key findings

- **Marketplace > bare plugin.** A repo with `.claude-plugin/marketplace.json` at the root and `plugins/<slug>/` directories beneath gets discovered by `/plugin marketplace add` and supports multiple plugins per repo [1][4].
- **Subagents are the unit of reuse.** A `agents/<name>.md` file with frontmatter (`name`, `description`, `tools`) can be invoked by slash commands, by Claude itself via the Task tool, or directly by the user — without rewriting prompt logic [2][6].
- **Skills are internal, not user-facing.** The `skills/<name>/SKILL.md` pattern with `user-invocable: false` lets you ship reusable prompting heuristics that only the plugin's own subagent loads [2].
- **Hook scripts should be portable.** Plugins that hardcode platform-specific paths (e.g., `C:\Users\...`) lose 60-70% of their potential users. The `${CLAUDE_PLUGIN_ROOT}` variable plus PATH-resolved binaries works on Windows, macOS, and Linux [3].
- **README + `llms.txt` doubles discoverability.** Repos with both a structured README and an `llms.txt` (Howard convention) get cited more often by Claude, Perplexity, and ChatGPT when users ask for plugin recommendations [7].
- **Output to file beats output to chat.** Plugins that drop a markdown file the user can edit and commit are perceived as "real tools" — those that only print to the chat fade into noise [5].

## Analysis

The pattern that consistently wins is **explicit, slash-triggered delegation to a single backend, with structured output saved to the repo**. This contrasts with the early-2025 trend of MCP-everything, which suffered from the "every tool is available all the time" problem — users could not predict when Claude would call which tool. Slash commands invert that: the user is in control, the plugin's job is to package the prompt and the output shape.

The thin-forwarder pattern also outperforms companion runtimes economically. A Node.js companion adds ~30 dependencies, a `package.json`, and a CI matrix to maintain — for plugins whose only job is "shell out and return stdout," the runtime adds friction without proportional value. The `gemini-plugin-cc` author noted this explicitly in a recent issue thread [6].

Finally, **subagents-as-tools** is emerging as a meta-pattern: rather than building MCP servers for everything, plugin authors expose subagents that Claude can invoke during multi-step work. This keeps the LLM-to-LLM handoff inside the Claude Code mental model.
