Antigravity Plugin · Claude Code

Un RAG local para Claude Code
que ahorra tokens

Reemplazo de NotebookLM, adentro de Claude Code. La lectura pesada de una carpeta entera de documentos ocurre en Google Antigravity (agy / Gemini), no en el contexto de Claude.

¿Es esto un RAG? Sí. RAG = Retrieval-Augmented Generation: primero recuperás los fragmentos relevantes de tus documentos, después el modelo genera la respuesta apoyándose en ellos — con citas. Eso es exactamente lo que hace /agy:notebook + /agy:notebook-query, pero local y sin pagar tokens de Claude por leer los documentos.

Cómo funciona, paso a paso

01 · TUS DOCSUna carpeta PDFs, escaneos, imágenes, docx. Pueden ser cientos de páginas.
→
02 · agy / GEMINILee y extrae agy lee cada documento (OCR incluido) y escribe un resumen + un .facts.json estructurado por documento. Todo ocurre en Gemini.
→
03 · notebook.dbÍndice local (RAG) Un SQLite con entidades, montos, fechas, referencias + FTS5 (keyword) y, opcional, vectores (embeddings). Cada fila cita su documento.
→
04 · CLAUDEPregunta y cita Claude consulta la DB con SQL y responde con la fuente — sin volver a leer los documentos crudos.

Por qué ahorra tokens

Pegar 200 páginas en el chat se las come el contexto de Claude (y se te va el presupuesto de tokens). Acá Claude solo orquesta y lee el índice; el texto pesado nunca entra a su ventana.

Pegar los docs en Claude
RAG local (este plugin)
La lectura corre en Gemini vía agy. Claude recibe solo la síntesis y las filas que pide — una fracción de los tokens.

Dos formas de recuperar

Por defecto · 0 dependencias

Keyword (FTS5)

Búsqueda full-text con plegado de acentos. Exacta para nombres, montos, números, términos. Siempre disponible, sin instalar nada.

Opt-in · --semantic

Semántico (vectores)

Embeddings de los fragmentos en una tabla sqlite-vec. Encuentra por significado, no solo por palabra exacta. Se fusiona con la keyword usando RRF (Reciprocal Rank Fusion).

🔎 Híbrido = lo mejor de los dos. Con --semantic, una pregunta conceptual combina el ranking keyword (FTS5) y el vectorial (KNN) y los fusiona con RRF, así no se te escapa ni el término exacto ni el sinónimo. Sin --semantic, FTS5 + SQL estructurado ya resuelven la mayoría de las consultas.

Se ve así

# 1) construir el RAG sobre una carpeta (opcional: + búsqueda semántica)
/agy:notebook  ./docs | objetivo: decisiones, responsables, montos, fechas  --semantic

# 2) preguntar — respuestas exactas y CITADAS
/agy:notebook-query  ./docs | sumá los montos por categoría
→ infraestructura $12.400, marketing $8.100  (cita: REP-0042, NOTE-0090)

/agy:notebook-query  ./docs | qué documentos mencionan "Acme Corp"
→ 3 documentos: REP-0042, MIN-0007, MAIL-0031

Qué hace al RAG confiable

cada fila cita su documento montos en centavos enteros (sin error de redondeo) 0 filas → "no aparece en el corpus", nunca inventa incremental (solo re-lee lo que cambió) local + privado sin runtime de Node
